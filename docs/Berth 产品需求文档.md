## 1. 产品定义  
  
Berth 是一款只驻留在 macOS 顶部菜单栏的原生工具，用来查看、识别并释放本机正在监听的端口。  
  
它解决的是 vibe coding 场景里的具体问题：编辑器和 AI 会同时拉起多个 Next、Vite、Nest、Python、Docker 服务。用户看不到这些口被谁占着，一旦出现 `EADDRINUSE`，就只能去终端查 `lsof`、猜 PID、再 `kill`。  
  
Berth 的闭环是：  
  
**看见谁占了口 → 判断能不能杀 → 停掉 → 确认口已经空出来。**  
  
看板是入口，停进程是主功能。第一版不做「只能看不能杀」的半成品。

## 3. 目标用户  
  
**主用户：** 同时开多个本地项目的开发者，尤其是用 Cursor、Claude Code、Codex、Copilot 辅助编程的人。  
  
**次用户：** 需要快速确认 3000 / 5173 / 8080 / 5432 占用情况的前端、后端、DevOps。  
  
**非目标：** 企业网络扫描、渗透、远程主机、流量抓包。Berth 只管理本机监听端口。  
  
---  
  
## 4. 产品形态（硬约束）  
  
1. 启动后只出现在顶部菜单栏。  
2. 不常驻 Dock`Info.plist` 设置 `LSUIElement = YES`。  
3. 默认不出现在 Cmd+Tab。打开设置窗口时可临时激活，关闭后回到 accessory。  
4. 无主窗口启动。第一次使用就是点菜单栏图标。  
5. 原生实现：Swift + SwiftUI / AppKit，不做 Electron。  
6. 本地优先：不上传端口、进程、路径、命令行。  
7. 轻量：后台刷新时 CPU 接近 0，内存建议小于 50MB。  
  
---  
  
## 5. 设计原则  
  
- 打开面板后 1 秒内看懂「现在有什么在跑」。  
- 默认隐藏系统端口，突出开发端口。  
- 列表不要只显示 `node`，要显示项目和框架，例如 `next · blog-web`。  
- 杀进程默认安全：先 `SIGTERM`，确认后再 `SIGKILL`。  
- 系统关键进程禁止杀。  
- 菜单栏图标极简，信息密度放在弹出面板。  
- 不为 AI 而 AI。项目识别靠 cwd、命令行、仓库和包文件，数据不出本机。  
  
---  
  
## 6. 用户场景  
  
### 6.1 启动冲突  
AI 起 Next.js，终端报 3000 被占用。打开 Berth，看到 `3000 · next · blog-web · ~/code/blog`，点「停止」，旧进程退出，口被释放。  
  
### 6.2 多项目并行  
同时跑管理后台 3000、营销站 5173、Nest API 4000、Postgres 5432。按项目分组，而不是一长串 `node`。  
  
### 6.3 幽灵进程  
编辑器关了，Vite 还在听口。Berth 里能停掉，并且要连子进程一起停，避免父死子占口。  
  
### 6.4 误点保护  
用户看到系统端口或数据库端口时，不能一键误杀。系统项禁用；数据库放进「更多」，并写明风险。

## 7. 功能需求  
  
### 7.1 v0.1（必须做完）  
  
#### F1 菜单栏入口  
- template 图标，可选数字角标（开发端口数）。  
- 点击弹出面板`MenuBarExtra` 的 `.window`，或 `NSPopover`）。  
- 面板宽度 360–420pt，最大高度约 560pt，超出滚动。  
- 杀进程过程中图标可短暂进入忙碌态，结束后恢复数字。  
  
#### F2 监听端口发现  
- 扫描本机 TCP LISTEN。UDP 不做。  
- 每条记录至少包含：端口号、绑定地址`127.0.0.1` / `::1` / `0.0.0.0` / `*`）、协议、PID、进程名、用户。  
- 打开面板立即刷新。  
- 后台默认 3 秒轮询，可在设置里改为 1–15 秒。  
- 停止进程后立即再扫一次，不等下一个轮询。  
  
#### F3 开发者可读信息  
- 解析进程 cwd。  
- 项目名优先级：git 仓库名 → 目录名 → `package.json` / `pyproject.toml` / `Cargo.toml` / `go.mod` 的 name。  
- 从命令行识别常见栈：Next、Vite、Nuxt、Nest、Express、Django、FastAPI、Uvicorn、Rails、Spring、Docker、Postgres、Redis、Mongo。  
- 主标题格式`框架 · 项目名`。识别不出框架时退回进程名。  
  
#### F4 分组与过滤  
- 默认分组：开发服务 / 数据库与中间件 / 容器 / 系统 / 其他。  
- 系统组默认折叠或隐藏，可一键展开。  
- 顶部搜索：端口、进程、项目名、路径。  
- 快捷过滤：仅开发端口、仅关注端口、仅 `0.0.0.0` 暴露端口。  
  
#### F5 单条查看操作  
- 浏览器打开 `http://localhost:{port}`[。](http://localhost:{port}`。)  
- 复制 URL / 端口 / PID / cwd / 完整命令行。  
- 在 Finder 中显示项目目录。  
  
#### F6 停止端口（v0.1 主功能）  
  
每条**可杀的开发端口**提供：  
  
| 动作 | 行为 | 交互 |  
|---|---|---|  
| 停止 | 对该口所有 LISTEN PID 发 `SIGTERM`，最多等 2 秒 | 主按钮，开发端口无需预确认 |  
| 强制结束 | 发 `SIGKILL` | 放在「更多」里，必须二次确认 |  
| 结束进程树 | 先子后父，或对进程组操作 | 对 node / python / vite / next 默认启用 |  
  
规则：  
  
1. 按端口停，不只杀当前行看到的那一个 PID。同一端口的 IPv4 + IPv6 LISTEN 一次清干净。  
2. 先 `SIGTERM`，200–500ms 后复扫；仍在则等到 2 秒。  
3. 仍占用则提示「仍被占用，是否强制结束」，或等用户自己点强制结束。  
4. 对 node / vite / next / python，必须处理子进程。不能出现父进程退出、子进程继续占口。  
5. 杀完立即 `scanOnce()` 刷新列表。  
6. 成功提示写在面板底部，例如「已释放 :3000」。不要用系统通知刷屏。  
7. 失败说人话：权限不够、进程已退出、受保护进程、口处于 TIME_WAIT（此时不要显示成杀失败）。  
  
行内结构：  
  
```  
3000  next  blog-web  127.0.0.1  
[打开] [停止] [···]  
```  
  
「更多」中提供：强制结束、结束进程树、复制 PID、忽略此端口。  
  
#### F7 杀进程安全策略  
  
默认能杀：  
- 当前用户的开发服务  
- 关注端口上的普通开发进程  
  
默认不能杀（按钮禁用，并显示原因）：  
- `kernel_tasklaunchdWindowServersyslogdmDNSResponder` 等系统进程  
- 明确属于系统关键服务的 root 守护进程  
  
数据库与中间件（Postgres / Redis / Mongo 等）：  
- 允许杀，但不放主按钮  
- 放进「更多」，文案标明「这是数据库，停掉会影响本机项目」  
  
绑定 `0.0.0.0` 的开发服务给出「局域网可见」提示，但不阻止停止。  
  
#### F8 设置  
- 登录时启动`SMAppService`）  
- 刷新间隔  
- 菜单栏是否显示数字  
- 是否显示系统端口  
- 关注端口列表，默认：    
  `3000, 3001, 4000, 4173, 5000, 5173, 5432, 6379, 8000, 8080, 8888, 9000, 27017`  
- 退出 Berth  
  
设置用独立小窗口，不要塞进弹出面板。从面板齿轮打开。打开时允许应用临时激活，避免输入框抢不到焦点。  
  
#### F9 空状态与错误  
- 无开发端口：显示「目前没有开发服务停靠」。  
- 扫描失败：显示原因和重试，应用不得崩溃。  
- 停止失败：保留该行，给出失败原因。  
  
### 7.2 v0.2（第一版之后）  
  
- 关注端口被未知进程占用时，菜单栏图标进入警告态  
- Pin 常用项目  
- 按端口 / 进程 / 路径忽略  
- Docker / OrbStack / Colima 显示容器名和映射端口  
- 运行时长、CPU、内存采样  
- 全局快捷键打开面板，默认 `⌥⌘P`，可改  
- 按项目一键停止该项目下全部开发端口  
- 停 Docker 时尽量停容器，而不是只杀 `docker-proxy`  
  
### 7.3 v0.3（可选差异化）  
  
- 幽灵进程标记：父终端或编辑器已退出  
- 沿父进程链尝试关联 Cursor / VS Code / Warp / Terminal / iTerm  
- 局域网 URL 与二维码  
- HTTP 探测：是否响应、页面 title  
- CLI`berth lsberth kill 3000`，方便给 agent 调用  
- 关注端口占用变化通知（默认关闭）  
  
### 7.4 明确不做  
  
v1 不做：远程主机、端口转发管理、抓包、账号体系、云同步、强制接入大模型、杀进程后自动重新拉起。

## 8. 界面结构  
  
### 8.1 菜单栏  
- 默认：图标

- 正在停止：短暂忙碌态  
- v0.2 冲突：警告态，仍保持克制

```  
[搜索框]
```  

正文`强制结束 pid 18422（next · blog-web）？未保存状态会丢。`

## 10. 技术方案  
  
- 语言：Swift 5.10+ / Swift 6  
- UI：SwiftUI + 必要 AppKit  
- 菜单栏`MenuBarExtra` + `LSUIElement = YES`  
- 登录项`SMAppService`  
- 扫描`lsof -nP -iTCP -sTCP:LISTEN -F pcPnTu`  
- 按端口取 PID`lsof -tiTCP:PORT -sTCP:LISTEN`  
- 进程详情`proc_pidpath`、cwd`ps` 命令行  
- 停止`kill(pid, SIGTERM)`，超时或用户确认后 `SIGKILL`  
- 子进程`pgrep -P pid` 或进程组  
- 模块划分：  
  - `PortScanner`  
  - `ProcessEnricher`（cwd / 项目 / 框架）  
  - `ProcessTerminator`  
  - `PortStore`  
  - `MenuBarView` / `SettingsView`  
  
框架识别表示例：  
  
| 命令行特征 | 显示名 |  
|---|---|  
| `next` / `next-server` | Next.js |  
| `vite` | Vite |  
| `nuxt` | Nuxt |  
| `uvicorn` / `gunicorn` | Python API |  
| `postgres` | PostgreSQL |  
| `redis-server` | Redis |  
| `com.docker` / `docker-proxy` | Docker |  
  
识别规则做成可扩展表，不写死在 View 里。

## 12. 验收标准（v0.1 过线）  
  
1. 启动后 Dock 无图标，只在菜单栏出现。  
2. 本地执行 `npx serve -p 3456` 后，3 秒内面板出现 3456。  
3. 同时跑两个 node 项目时，能按 cwd 分成两个项目，而不是两个「node」。  
4. 点「打开」，浏览器访问对应 localhost。  
5. 点「停止」后，serve 退出，3456 在立即复扫后从列表消失。  
6. 同一端口同时存在 `*:3000` 和 `[::1]:3000` 时，一次停止两边都掉。  
7. Vite / Next 这类父子进程停止后，口真正空出来。  
8. `mDNSResponder` 等系统项没有可用的「停止」按钮。  
9. 数据库端口的停止入口不在主按钮上。  
10. 强制结束有确认；点取消则什么都不发生。  
11. 系统端口默认不刷屏。  
12. 退出 Berth 后无残留后台进程。

## 13. 风险与边界  
  
- 新系统菜单栏第三方图标可能不稳定，需在目标 macOS 上实机验证。  
- App Store 沙盒可能限制读取其他进程；v0.1 按独立分发设计。  
- 停止进程有误杀风险，必须靠保护名单和确认框兜住。  
- Berth 只显示 LISTEN，不显示纯出站连接。产品文案要写清楚。  
- TIME_WAIT 不是进程还活着，UI 不能把它当成停止失败。

## 14. v0.1 范围冻结
